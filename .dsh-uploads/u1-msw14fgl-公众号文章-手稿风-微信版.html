缘起

最初的问题很简单：能不能让这个 DeepSeek 智能体跟我实时语音对话？调研了一圈国内模型，发现一个尴尬的事实——

  • Kimi K3：只有文本和图像，没有音频，只能自己拼管线；
  • 豆包实时语音 3.0 / Qwen-Omni / GLM-Realtime：确实能全双工语音对话，但跟你聊的是它们自己的模型——你的会话上下文、你挂的工具，它一概不知。

而我要的是：大脑还是当前这个智能体，语音只管进和出。

八个坑全记录

真正的故事从这里开始。每个坑都按「症状 → 根因 → 修法」三栏拆开，方便后来者对号入座。

第一难

鉴权对不上，一上来就吃 400

症状｜火山语音有两代鉴权：旧的「App ID + Access Token」，新的「单个 API Key」。我接的库走旧鉴权，手里的却是新 Key，直接调就是 HTTP 400。

修法｜不重写协议，monkey-patch 换掉鉴权头——只换 X-Api-* 那几个 header，二进制帧协议原样复用。

_wsc._build_headers = lambda app, token, res, rid: {
    'X-Api-Key': api_key,
    'X-Api-Resource-Id': res,
    'X-Api-Connect-Id': uuid4(),
    'X-Api-Request-Id': rid or uuid4(),
}

第二难 · 最诡异

「双音」：两个声音各读各的

症状｜回答读到一半，突然变成两个声音、各读一段，深夜听起来像有人在跟 AI 抢话筒。这个 bug 耗我最久。

根因｜后端逐句合成，上一句 mp3 还没播完，下一句 tts_done 就到了，浏览器 new Audio().play() 直接并发放——两句叠在一起了。

修法｜播放改成顺序队列，前一句 ended 才出队播下一句：

let currentAudio = null
const pendingBlobs = []
function pump() {
  if (currentAudio || pendingBlobs.length === 0) return
  const item = pendingBlobs.shift()
  currentAudio = new Audio(item.url)
  currentAudio.onended = () => { currentAudio = null; pump() }
  currentAudio.play()
}

✎ 根因简单得让人想笑，但找到它花了一整晚

三至六难

四个「小」坑，每个都让人愣一下

🔁 它把上一轮的回答又读了一遍

新一轮刚开始、新回答还没生成，这时「最后一条回答」还是旧的，朗读器当成新内容重读了。给每个回答行记个身份（data-chat-anchor-key），回合开始记 baseline，只读本轮新出现的行。

🗣️ 它读了我自己的话，还读了思考过程

一开始抓的是「最后一行」，用户语音输入和英文推理全被念了。好在 DOM 里有现成的标记：用户消息是 data-chat-flow-kind="user"、回答是 assistant-step、思考块是 data-variant="think"。只抓回答行、剔除 think 块，立刻干净了。

⌨️ 键盘打字也朗读

需求是「语音进才语音出，打字就安静回文字」。加一个 speakThisTurnRef 标记：只有语音识别到完整句（final）自动发送的回合才朗读。

#️⃣ 符号全被读出来

**加粗**、# 标题、代码块、裸链接、emoji 直接丢给 TTS，会被一个字一个字念出来。送进去前先做一轮文本清洗，只留自然语言。

第七难

30 个音色，一半是「李鬼」

症状｜用户要「排名前 30 的音色，还都要验证过」，但火山音色 ID 命名太像了——_moon_bigtts、_mars_bigtts 这类后缀其实是 seed-tts-1.0 的旧音色，丢进 2.0 接口直接报 resource mismatch。

修法｜名字不能信，用真实 API Key 逐个合成实测。最终跑出 30 个真正可用的中文音色（女声/男声/童声/角色音都有），全部返回超过 1000 字节的有效 mp3。

✎ 名字会骗人，API 不会

第八难

API Key 的隐私

Key 是敏感信息。设置页输入框默认 password 遮罩，加了 👁 显示/隐藏切换；后续还可以接入 DSH 的 credentials 服务托管，而不是存 localStorage。

复盘 · 三条最值钱的判断

①「让当前智能体当大脑」决定了整个架构。
不是换一个语音模型，而是语音只做输入输出层，智能体一行没动。

② 能复用就复用，别手搓协议。
火山二进制协议自己写容易错，patch 一个鉴权头比重写整套稳得多。

③ DOM 标记是宝藏。
data-chat-flow-kind、data-variant 这些语义标记，让「只读回答、跳过思考、跳过用户消息」变成一行选择器的事。
